# Airy Flow mobile-host WebView selective port — implementation plan

> Implement task by task with focused tests and review. This document is planning only; do not infer authority to deploy, migrate, or commit from it.

**Goal:** Make the web routes used by the iOS Flutter WebView current and functional on `mobile.mystudentclub.com`, including resource lead forms, while keeping the present full-screen Airy Flow page chrome.

**Architecture:** Start from the verified mobile-host source (provisionally `mobile-bugs` `04ccbd5a9`), then selectively adapt behavior/content from canonical `upstream/master` `129251eab` and `origin/msc-overhaul-v2` `f8430d53d`. Preserve each mobile page's header, footer/bottom navigation, CSS tokens, safe-area padding and light/dark behavior; do not merge master wholesale or introduce an embedded/no-chrome mode. Deploy backend contracts separately before exposing gated resources. The Flutter [native parity plan](../../../../msc-app/docs/superpowers/plans/2026-10-11-native-ios-master-parity.md) owns native links, Profile interception exception and app release.

**Tech stack:** Static HTML/CSS/JavaScript, Supabase Auth/PostgREST/Storage, Cloudflare-hosted mobile site, Cloudflare notify Worker, Node `node:test`, Flutter `InAppWebView`/iOS `WKWebView` verification.

**Spec:** [Airy Flow mobile-host WebView port design](../specs/2026-10-15-airy-flow-mobile-web-port-design.md).
