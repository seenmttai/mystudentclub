# Airy Flow mobile-host WebView port — design

Date: 2026-10-15

## Decision and boundaries

Port only the web content and behavior that the Flutter app opens, or is about to open for the agreed resource and placement flows, into the Airy Flow mobile site. `mobile-bugs` at `04ccbd5a94355955781e4e87fcee6f40f3b3b8d7` is a **provisional** integration baseline. Canonical input is `upstream/master` at `129251eababaf4146dc13850f5e5ec1898fdf97c`; resource input is `origin/msc-overhaul-v2` at `f8430d53dd028ba8f3fe74fc4297ae1959ae4225`. Confirm the deployed source branch and commit for `mobile.mystudentclub.com` before implementation or release. Do not merge either upstream branch wholesale: their divergence includes unrelated desktop UI and generated job pages.

The app must retain its current full-screen WebView. `msc-app/lib/core/app_router.dart` opens drawer tools with `showAppBar=false`; `msc-app/lib/features/shell/main_shell.dart` deliberately omits the native bottom bar for embedded LMS because the LMS page owns navigation. Therefore retain the Airy Flow web header, footer and, where present, web bottom navigation. Do **not** add an embed/chrome-hiding query mode or a Flutter shell wrapper. Preserve mobile color/theme tokens, body layout, safe-area treatment, and navigation affordances. Keep native Home, Job Detail, Applied, Profile and Login work in the separate [Flutter native plan](../../../../msc-app/docs/superpowers/plans/2026-10-11-native-ios-master-parity.md); this companion document owns only mobile-host web files and their deployment prerequisites.

## Data, auth and media contracts

The resource port must retain real stage-specific lead capture, not just its visual form. Overhaul `scripts/career-profile.js` and `scripts/resource-form-collector.js` drive stage fields and consent. `supabase/migrations/202609270001_career_intake.sql` defines `submit_career_intake(p_stage,p_details,p_source)` and persistence to `career_intakes`/profile/consent; `database/20260927-public-resource-catalog-v2.sql` defines `get_public_resource_catalog_v2`, with the existing `get_public_resource_catalog` fallback used by `scripts/resource-library.js`. Premium entitlement is checked via `scripts/program-access.js` and `enrollment`; protected files use the `industrial-training-mastery-resources` storage bucket and `/ca-resource/resource/index.html`. These are backend deployment gates, not static HTML. Verify RLS, authenticated and anonymous intake, catalog names-only output, enrolled access, and non-enrolled denial before showing the new cards.

Flutter injects the Supabase session under `sb-izsggdtdiacxdsjjncdq-auth-token`, plus `msc-theme`, before page scripts; mobile pages must use the same authenticated session and preserve logout/account switching. The overhaul `scripts/supabase-init.js` and protected viewer create clients without an explicit storage key, so test and correct this mismatch at the web boundary before release. Free DOCX/PDF downloads, premium signed URLs, iOS file upload, blob downloads, and PDF preview must work in `WKWebView`; a preview implemented with `window.open(..., '_blank')` needs explicit verification because the current Flutter WebView has no `onCreateWindow` handler. Keep the existing blob bridge and avoid replacing functional download buttons with links that silently fail.

The Got Placed card sends the current user's token to `https://notify.mystudentclub.com/placed/start` and follows only the Worker's `/placed` form URL. The Worker source is outside this repo. Release is gated on an externally deployed, reachable Worker, authenticated start response, iPhone navigation, and offer-letter picker/upload; no web mock or native form substitutes for it.

## Visual and release constraints

Master commit `35bc7e5d8` replaces `assets/logo.png`, favicons and related assets without changing paths. Port the approved assets selectively. Airy Flow page headers often contain the **old inline SVG** (`.header-logo` in LMS, resource and program pages, reviews/contact); the asset replacement alone will not change those. Replace only the visibly stale inline logo on in-scope headers with an appropriately sized new asset/vector, preserving their layout and tap target. Do not blindly replace all ~9,000 generated-page marks.

Release sequence: prove mobile-host source mapping; prepare isolated selective port; deploy backend migration/catalog and verify protected storage/Worker; deploy the web site; verify distinct route content, exact auth/resource/placement journeys on desktop-mobile and physical iPhone; only then enable Flutter links and ship the separate native change. Roll back the mobile web deployment if route, entitlement, intake, registration or auth smoke fails; disable new app links if the site cannot be restored promptly. Existing app-opened routes must continue working throughout.

Acceptance: each enabled route yields its own content (not root fallback), full-screen Airy Flow chrome remains navigable, light/dark and safe areas remain correct, forms persist with consent, gated resources deny unauthorised access, downloads/previews/opening the placement Worker work on iPhone, and previously working LMS/CV/interview/reviews/contact pages remain intact.
